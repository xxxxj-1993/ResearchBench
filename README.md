# ResearchBench（科研工作台）

> 面向高校教师的 Windows 本地科研工作台。集中管理论文、课题、项目、教学成果、专利、课表、灵感与日程。

**当前版本：v2.4.3** · **支持 Windows 10 / 11** · **单文件约 10 MB** · **双击即用，无需安装 Python**

[下载最新版本](../../releases/latest) · [提交问题或建议](../../issues)

> [!IMPORTANT]
> ResearchBench 采用本地优先设计。论文、项目、日记等工作数据只保存在你的电脑中，不需要注册账号，也不会自动上传或同步。
>
> 核心功能可以完全离线使用。只有在你主动使用 DOI 导入功能时，软件才会访问 Crossref 查询公开的论文元数据。

## 为什么做这个

每年十一二月，学院开始收年度考核材料。通常要在一周内整理出：

- 今年发表或录用了几篇论文；
- 哪些论文是第一作者或通信作者；
- 在研项目推进到了哪一步；
- 学生大创是否结题；
- 专利号和授权状态是什么；
- 指导学生参加竞赛获得了什么奖项。

这些信息其实都在电脑里，只是散落在不同的文件夹、表格和软件中。每次整理材料，都要重新翻上两三天。

更麻烦的是，我经常回答不了一个很简单的问题：

> 我现在有多少件事情正在推进，它们分别卡在了哪里？

普通待办工具管理的是一条条任务，而 ResearchBench 更关注论文、课题和项目本身，以及它们所处的完整阶段。

一篇论文可以按照下面的流程推进：

```text
选题 → 理论 → 仿真 → 实验 → 写作 → 投稿 → 返修 → 接收
```

打开工作台，可以直接看到：

- 哪些论文还在做仿真；
- 哪些论文正在返修；
- 哪篇论文刚刚投稿；
- 哪个课题即将到期；
- 下一步具体要做什么。

项目可以关联论文，日程也可以关联论文或课题。因此，日历中显示的不再是一条缺少上下文的“返修截止”，而是类似下面这样的完整记录：

```text
《XXX》返修截止日期
投稿期刊：Journal of XXX
```

已发表论文还可以标记最多 5 篇代表作。填写职称材料、基金简历、年度考核或“近五年代表性成果”时，不必再临时翻找和回忆。

ResearchBench 解决不了科研本身的问题。选题好不好、实验能不能做出来、基金能不能获批，最终还是取决于研究工作本身。

它做的事情很有限：把散落的信息集中起来，让我少花一点时间找东西、记位置和核对进度。

## 主要功能

### 今日

默认打开的工作页面，包括：

- 当天日程时间线；
- 近期截止事项；
- 正在推进的论文和课题；
- 下一步行动汇总；
- 专注计时器。

高校教师的时间经常被课程、会议和临时事务切成很多小块。打开软件时，不必先面对全部事项，只需要看看今天应该做什么。

### 日历

- 支持月视图和周视图；
- 点击空白位置即可新建日程；
- 可直接拖动事件调整日期；
- 日程可以关联论文或课题；
- 日历内容带有对应的项目上下文。

### 课表

- 一周课表网格；
- 本学期课程总表；
- 按行课周次筛选课程；
- 支持从 Word、WPS、Excel 和网页表格粘贴导入；
- 导入前提供可勾选、可修改的确认页面。

课表导入流程：

1. 在 Word、WPS、Excel 或网页中选中整张课表；
2. 复制表格；
3. 打开“课表 → 导入课表”；
4. 在输入区域按下 `Ctrl + V`；
5. 输入自己的姓名，筛选属于自己的课程；
6. 检查并修改识别结果；
7. 确认后导入。

不同学校的课表格式差异较大，建议在导入前人工核对一次。

### 论文

按照完整科研流程跟踪论文进展：

```text
选题 → 理论 → 仿真 → 实验 → 写作 → 投稿 → 返修 → 接收
```

每篇论文可以记录：

- 目标期刊；
- 当前阶段；
- 投稿轮次；
- 编辑决定；
- 作者顺序；
- 本人角色；
- 截止日期；
- 下一步行动；
- 进展记录；
- 关联课题或项目。

### 课题

用于管理正在推进的课题和研究任务，包括：

- 课题编号与名称；
- 本人角色；
- 当前状态；
- 完成进度；
- 截止日期；
- 关联论文。

### 已发表

用于管理已经发表或录用的论文：

- 按“全部 / 第一或通信 / 合作 / 代表作”筛选；
- 最多标记 5 篇代表作；
- 支持粘贴 BibTeX 批量导入；
- 支持通过 DOI 查询并导入论文信息；
- 可一键复制引用格式。

> DOI 查询需要访问 Crossref，其余 BibTeX 解析均在本机完成。

### 已立项

科研项目台账，包括：

- 在研与结题分组；
- 项目编号；
- 项目经费；
- 起止时间；
- 本人角色；
- 当前状态。

### 教学成果

用于记录：

- 教学竞赛与学生竞赛获奖；
- 荣誉称号；
- 教材编写；
- 教改论文；
- 大学生创新创业项目；
- 其他学生指导项目。

### 专利

集中管理专利信息和当前状态。

### 灵感

- 随手记录研究想法；
- 可一键写入 Obsidian；
- 默认写入 Obsidian 的“灵感”文件夹；
- 可将灵感直接转化为论文记录。

### 日记

- 按日期记录日常内容；
- 可设置 4 位 PIN，防止他人随手查看。

> 4 位 PIN 只用于防误看，不属于安全加密。请勿将其当作敏感信息保护方案。

### 常用入口

集中管理：

- 常用文件夹；
- 本地软件；
- 常用网址。

支持拖拽排序和重新探测本机软件。

当前内置 46 款常见科研软件的识别规则，分为五类：

- 仿真计算；
- 三维建模；
- 绘图图像；
- 文献写作；
- 数据分析。

第一次启动时，软件会自动扫描本机已经安装的科研软件，并将识别到的程序加入“常用”页面。未识别的软件也可以手动添加。

### 自定义导航名称

左侧导航名称可以修改。

在任意导航项上单击右键，选择“重命名”，即可直接输入新名称：

- `Enter`：保存；
- `Esc`：取消；
- “恢复默认名称”：还原原始名称。

自定义名称最长为 12 个字，并保存在本地数据文件中。修改后，导航名称和页面标题会同时更新。

### Zotero 与 Obsidian 联动

ResearchBench 不打算代替 Zotero 或 Obsidian。

- Zotero 继续负责文献管理；
- Obsidian 继续负责长期笔记和知识沉淀；
- ResearchBench 负责集中入口、进度管理和碎片记录。

顶部全局搜索可以同时检索：

- ResearchBench 中的论文、课题和其他记录；
- Zotero 文献；
- Obsidian 笔记。

搜索到 Obsidian 笔记后，可以直接跳转打开。

### 快捷键

| 快捷键 | 功能 |
|---|---|
| `Ctrl + K` | 打开全局搜索 |
| `Ctrl + N` | 在任意页面快速记录 |
| `Esc` | 关闭当前弹窗 |

软件支持中文与英文界面切换。

## 下载与运行

前往 [Releases](../../releases/latest)，下载：

```text
ResearchBench-v2.4.3.exe
```

文件大小约为 10 MB。下载后直接双击运行，不需要安装 Python，也不需要配置其他依赖。

第一次启动时，软件会：

1. 创建本地数据目录；
2. 启动仅供本机访问的服务；
3. 打开工作台窗口；
4. 扫描本机已经安装的科研软件。

关闭工作台窗口后，程序会退出。

### Windows 安全提示

由于当前版本没有商业代码签名证书，Windows SmartScreen 可能显示“未知发布者”。

请只从本仓库的 Releases 页面下载安装包。确认下载来源无误并完成安全检查后，可以点击：

```text
更多信息 → 仍要运行
```

如果杀毒软件提示风险，不建议直接关闭安全防护或立即添加白名单。请先确认：

- 文件是否来自本仓库的 Releases 页面；
- 文件名和版本号是否正确；
- 文件哈希是否与发布页面提供的校验值一致；
- 本地杀毒软件或 VirusTotal 的检测结果是否属于常见误报。

## 数据存储与备份

软件数据默认保存在：

```text
C:\Users\<你的用户名>\AppData\Roaming\ResearchWorkbench\
```

也可以在资源管理器地址栏中输入：

```text
%APPDATA%\ResearchWorkbench
```

目录内容如下：

```text
ResearchWorkbench\
├── data.json
├── zot_snapshot.sqlite
└── app.log
```

| 文件 | 用途 |
|---|---|
| `data.json` | 保存论文、课题、已发表论文、项目、教学成果、专利、灵感、日记、日程、快捷入口和材料信息 |
| `zot_snapshot.sqlite` | Zotero 数据库的只读快照，避免 Zotero 运行时锁定原数据库 |
| `app.log` | 程序运行日志，出现问题时可用于排查 |

### 备份

可以使用以下任一方式：

- 复制 `%APPDATA%\ResearchWorkbench\data.json`；
- 在软件中选择“设置 → 导出 JSON 备份”。

### 换电脑

可以使用以下任一方式：

- 将原电脑的 `data.json` 复制到新电脑的相同目录；
- 在新电脑中选择“设置 → 导入恢复”。

### 完全重置

1. 关闭 ResearchBench；
2. 删除 `data.json`；
3. 重新启动软件。

程序会创建一个新的空白数据文件。

> [!WARNING]
> `data.json` 可能包含未发表论文、项目资料、日记和其他个人信息。可以使用 Git 做本地版本管理，但不要将该文件提交到公开仓库。

本仓库发布的是干净版本。所有模块首次打开时均为空，不包含示例内容和作者个人信息。

## 网络访问与隐私

| 操作 | 是否需要联网 | 说明 |
|---|---:|---|
| 管理论文、课题和项目 | 否 | 数据写入本地 `data.json` |
| 日历、课表和日记 | 否 | 完全在本机运行 |
| BibTeX 导入 | 否 | 在本机解析 |
| Zotero 检索 | 否 | 读取本地数据库快照 |
| Obsidian 检索与写入 | 否 | 访问用户指定的本地仓库 |
| DOI 查询 | 是 | 仅在用户主动查询时访问 Crossref |
| 自动云同步 | 不支持 | 当前版本没有云同步功能 |

后端只监听：

```text
127.0.0.1
```

这意味着服务只接受本机连接，不向局域网或互联网开放。

## 设计上的一些取舍

### 1. 使用系统 Edge，不打包完整浏览器

后端使用 Python 标准库中的 `http.server`，前端使用原生 JavaScript。构建时，前端资源会被内联进单个 HTML 文件。

程序通过系统自带的 Microsoft Edge `--app` 模式显示界面。窗口没有地址栏和标签页，使用方式接近普通桌面软件。

没有额外打包 Chromium 或 Electron，因此安装包可以控制在约 10 MB。代价是系统需要安装 Microsoft Edge，不过 Windows 10 和 Windows 11 通常已经自带。

工具应该像一把螺丝刀，拿起来就能用，不应该变成一台需要专门维护的机器。

### 2. 课表导入读取剪贴板 HTML

从 Word 或 WPS 复制表格时，剪贴板中会包含表格对应的 HTML，其中保留了表头、合并单元格等信息。

ResearchBench 使用标准库 `HTMLParser`，将带有 `rowspan` 和 `colspan` 的表格还原成二维网格，再根据“星期”和“节次”定位课程。

这样做有两个好处：

- Word、WPS、Excel 和网页表格都可以使用同一套导入方式；
- 不需要直接解析复杂的 `.docx` 内部 XML。

目前的代价是不能直接将 Word 文件拖入软件，必须先在原软件中选中表格并复制。

### 3. 自动识别结果必须人工确认

课表、论文和其他自动识别结果不会直接写入数据文件。

软件会先显示一张可以勾选和编辑的确认表。只有点击“导入”后，选中的数据才会正式写入。

自动识别的作用是减少重复劳动，不是替用户做决定。多一次确认，比悄悄写入错误数据更可靠。

### 4. 电脑中已经存在的信息，不再手动抄写

科研软件已经安装，安装路径通常也已经登记在系统中，因此 ResearchBench 会主动查找：

1. 枚举本机可用盘符并匹配软件识别规则；
2. 查询注册表中登记的安装目录；
3. 对重复结果进行排序和去重；
4. 优先选择 `Program Files` 中的正式安装版本；
5. 降低绿色版、便携版和软件包目录的优先级。

在当前测试环境中，整套扫描通常可以很快完成。实际耗时会受到硬盘数量、安装位置和电脑性能影响。

### 5. 不代替 Zotero 和 Obsidian

ResearchBench 只做浅层联动：

- Zotero 数据库只读；
- Obsidian 只向指定目录写入笔记；
- 原有文献库和笔记结构不需要迁移。

碎片想法可以暂存在工作台中，需要长期整理的内容再交给 Obsidian。

### 6. 修改后立即保存

软件没有单独的“保存”按钮。

内容发生变化后会自动写入本地数据文件，减少因忘记保存而丢失修改的情况。

## 从源码运行

### 获取源码

```powershell
git clone https://github.com/xxxxj-1993/ResearchBench.git
Set-Location ResearchBench
```

### 正常启动

```powershell
python app.py
```

程序会启动本地服务，并自动打开 Edge 工作台窗口。

### 仅启动本地服务

适用于调试或 CI：

```powershell
$env:RB_NO_WINDOW = "1"
python app.py
Remove-Item Env:RB_NO_WINDOW
```

### 打包 EXE

```powershell
python -m pip install pyinstaller
pyinstaller --noconfirm "科研工作台.spec"
```

打包结果位于：

```text
dist\科研工作台.exe
```

### 目录说明

| 路径 | 用途 |
|---|---|
| `app.py` | 后端入口与桌面窗口启动逻辑 |
| `ui/` | 前端界面，构建时内联为单文件 HTML |
| `seeddata.py` | 初始数据配置，分享版默认为空 |
| `tests/` | 冒烟测试及辅助测试脚本 |
| `tools/make_icon.py` | 生成应用图标 |
| `科研工作台.spec` | PyInstaller 打包配置 |

## 目前的限制

- 仅支持 Windows，目前依赖 Edge 的 `--app` 模式；
- 只支持单机使用，没有云同步；
- 多台电脑之间需要通过 JSON 导出和导入迁移数据；
- 日记的 4 位 PIN 只能防止他人随手查看，不提供加密保护；
- 引用次数不会联网自动更新，需要手动维护；
- 课表导入前需要在 Word、WPS、Excel 或网页中复制表格；
- 不能直接拖入 `.docx` 文件解析；
- BibTeX 在本机解析，但 DOI 查询需要访问 Crossref；
- 不同学校的课表结构差异较大，导入后仍需人工核对。
